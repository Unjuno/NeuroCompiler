# 改訂ロードマップ：NeuroCompilerの研究価値を反証する

## 研究目標

**最重要の仮説**：数式やPDEのsemantic IRを条件とした重み生成は、強い数値法や非学習初期化と比べ、少なくとも特定の問題族・精度要件・多数task利用条件では実用的な追加価値を持つ。

これは現状の結論ではなく**将来検証する仮説**である。Stage 7–9Rは汎用優位を示さず、むしろ否定的な対照を多く含む。

## 停止と分岐の基準

- P0が**FAIL**なら、「NNでないと実現できない」とは言わず、**symbolic front-end + numerical backend** を第一製品仮説にする。
- P1の誤受理が多ければ、ニューラル出力を独立した解として採用せず、あくまで数値ソルバーへのwarm startに限定する。
- 真の演算子OODで失敗すれば、既知関数族への条件付き補間として研究範囲を明記する。
- LLM-LoRAへの移行は、物理系での統制された利得が確立するまで優先しない。

## 再現実験の必須条件

数値・実装依存性：dtypeはFP32/FP64、BLAS backend/threads、PyTorch/NumPy/SciPy版、CPU/GPU種別、solver許容差、zero-point/正規化、モデルABI、batchとタスク分布を固定・記録する。FP32丸めによる相殺も独立に検査する。

**統計**：学習seedを独立単位とし、task bankの再利用を隠さない。多重検定を事前に調整し、途中で選んだ有利な評価量は探索的と明記する。3段階の精度閾値と、学習費用込みの総処理時間を登録する。

## 最初に処理するIssue

1. Stage 9Rの未学習Diagonal→Newton2の精度・実時間を学習済み生成器→Newton1と**同一HW/時間予算**で比較。
2. 36基底の投影誤差上界を、別参照格子と高解像度で検証。
3. 学習済み・非学習の双方に、共通の残差・数値補正・fallbackを接続したAB試験。
4. 重み生成とsolver route選択の反復・計算費用を固定bank上で測定し、原本hash付きで公開。

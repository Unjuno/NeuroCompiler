# 実験エビデンス・来歴・ラベル付け方針

## 原本の扱い

原本ZIP 9個のファイル名、ファイル数、SHA-256を [`archives/source_archives.csv`](../archives/source_archives.csv) に掲載。公開用リポジトリに選択したファイルの元アーカイブ内パスとSHA-256は [`archives/curated_source_map.csv`](../archives/curated_source_map.csv) に記録しています。

これは**保存ファイルの整合性と来歴**に関する監査であり、すべての数値実験を初期状態から独立再実行したことを意味しません。

## 証拠レベル

| ラベル | 意味 | 典型例 |
|---|---|---|
| A：確認済み | ファイルの存在/zip CRC/SHAを確認し、指定されたローカルテストを実行して成功 | Stage9R test 9件、原本ZIPのCRC検査 |
| B：保存済み分析 | 元レポート・CSVが存在し、数値を限定条件付きで転記 | Stage1–8/9Rの既存統計 |
| C：報告のみ | 会話上で結果が説明されたが、生データや実装を現ファイル群で確認できない | 旧Stage9。再現は未確認 |
| D：仮説 | まだ測定していない研究方針 | 同精度・総費用での優位、PDE汎用compiler |

研究の主張は条件・分布・独立性・結果の選択ルールに照らしてA/B/C/Dを明示する。上のAはファイル検査の合格であり、査読済みの正しさを保証しません。

## 既知の危険な解釈

- **Matchされたと言いながら初期lossが揃っていない**：Stage7では0/10seed、Stage1eのh20は3/20seedのみ成立。これらを因果的なgeometry比較に使わない。
- **GPU/CPU性能の推測**：同一CPU条件の結果を別HWへ外挿しない。
- **モデルが数学的意味を理解した**：Stage6bのrewrite不変性は、記号正規化器により強制されたもの。
- **タスク数を独立標本数として計上**：bootstrapは原則独立学習seedで行われ、固定bankに条件付く。
- **Stage9RがStage9を再現**：旧Stage9のコード/原本なし、9Rは独立再実装。
- **高精度の証明**：離散格子上の相対誤差・数値残差と、連続PDEの保証を混同しない。

## 原本の非破壊原則

アーカイブ内の生CSV/学習重みは書き換えない。集計値に誤りが見つかった場合は原ファイルを残して`docs/CORRECTIONS.md`に根拠と新しい計算方法を追記する。元の報告書を上書きして成功に見せることはしない。
